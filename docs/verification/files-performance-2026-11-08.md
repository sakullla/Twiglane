# 文件阅读与差异视图优化验证

验证环境：Windows，Node.js 26.4.0，Rust 1.99.1。未验证 CI 使用的 Node.js 22，也未验证 macOS/Linux 桌面运行。

## 行为与开销变化

- 文件正文使用当前文件的修改时间、创建时间和大小判定是否需要重读。目录扫描复用已有 metadata，不额外读取正文或计算整文件哈希。其他文件变化不会撤下正文、分页、滚动位置和文件内搜索命中。手动刷新仍强制重读；缺少文件版本时回退到仓库 generation。
- 分页响应携带同一元数据版本；续读发现文件已变化时重新读取，避免拼接新旧正文。
- 文件树的导航、类型解析与渲染共享派生行数组；未改变的目录保留子项数组。筛选用祖先路径集合替代“每个目录遍历全部匹配”的双重扫描。
- 一次目录重验按每批最多 3 个请求读取，父目录完成后才排入仍存在的已加载子目录。隐藏或切换仓库后停止排入后续批次。请求序号不在切仓库时重用，避免切走再回来时接受旧响应。
- 文件正文采用原始响应式状态，减少逐行代理开销；隐藏正文时取消高亮订阅。diff 并排宽度计算复用已有两侧文本，hunk 查询使用索引，没有删除行时不为旧侧额外分词。
- 单份高亮文档的结果采用 8 MiB 估算预算，超出后保留已有高亮，其余行仍显示原文。此预算不是整个应用的堆内存上限。
- 后端跳过前页行时不复制行内容，仍检查 NUL 和取消信号。超长行的 UTF-8 边界采用一次验证，非法编码不再被反复裁剪后误报成文本。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| `npm run check` | 0 errors，0 warnings |
| `npm test -- --maxWorkers=2` | 44 个测试文件，1041 项通过 |
| 最终目录数组复用调整后的文件树、导航专项复测 | 3 个测试文件，40 项通过 |
| `npm run test:performance -- --ui` | 11 项通过，包含两万文件、两万路径结果、多文件 diff 并发和虚拟渲染边界 |
| `npm run build` | 通过；仍有大于 500 kB 的 chunk 提示 |
| `cargo test --manifest-path src-tauri/Cargo.toml` | 244 项通过 |
| `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` | 通过 |
| `git diff --check` | 通过 |
| `npm run verify:delivery` | 未通过：仓库缺少 `docs/verification/report.json` |

新增回归覆盖：无关代次变化保持正文 DOM 和滚动位置、在途读取去重、文件内搜索保留、真实文件变化与手动刷新、分页版本变化、目录刷新并发和隐藏中止、删除子目录、切仓库旧响应隔离、文件元数据版本、高亮结果预算、长行非法 UTF-8。

第一次高并发运行全套前端测试时，一项语法着色断言失败；该套件单独复测通过，限制为两个 worker 后完整 1041 项通过。未修改该断言。

## 验证边界

没有测量桌面 WebView 帧率、进程峰值内存或长时间驻留内存；happy-dom 的 DOM 数量与请求预算测试不能替代这些测量。不声明内存下降百分比或完成跨平台发布验证。

元数据版本用于只读视图失效判断，不是内容哈希，也不用于暂存或其他 Git 写入授权。外部工具同时保留大小与全部时间戳时可使用手动刷新。

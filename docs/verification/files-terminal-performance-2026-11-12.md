# 文件与终端性能、资源释放验证

此文保留 11 月 12 日阶段性结果。后续测试整理移除了单元测试的计时输出，并将原生菜单测试收敛为纯事件路由；当前检查结果及命令见 [v0.3.12 验证记录](v0.3.12-performance-tests-2026-11-13.md)。

环境：macOS arm64，最终前端检查使用 Node.js 22.23.5；Rust/Cargo 1.98.1。真实 PTY 用例使用 `/bin/sh`，没有测量桌面 WebView 的整体 RSS、GPU 内存或用户 shell 配置的启动耗时。

## 修改与依据

- 终端关闭：交互 shell 会忽略 SIGTERM，原逻辑可能等满 2 秒再强制结束。Unix 改为 SIGHUP 挂断通知，超时仍升级 SIGKILL；Windows 保留 Job Object 终止。批量关闭先通知全部会话，共用宽限和退出等待窗口，避免按会话数量累加等待；前端关闭多个分屏也并行提交。
- 后代进程：新增用例让后台 shell 忽略 HUP/TERM、重定向标准输入输出并写心跳。修复前，父 shell 已退出且关闭成功后心跳仍从 6 字节增长到 14 字节。修复后，单个和批量关闭都继续清理关闭时捕获的后代集合，心跳停止。
- 终端内存：回放改用有界环形缓冲，保留 2 MiB 上限和 UTF-8 边界，饱和后不再每次搬移整段历史；显式约束底层分配容量，防止自动倍增。待推送输出达到 256 KiB 时暂停读取，实际可额外容纳一个解码块；推送恢复后继续，不主动丢弃实时输出。这不是 IPC 或整个应用内存的硬上限。
- 生命周期：退出后释放 PTY 输入句柄；订阅部分失败或卸载时释放已建立的监听器；附着失败后停止积累待回放事件；组件卸载期间才完成的新建/重启会话立即请求关闭。隐藏终端释放 WebGL 渲染器，恢复显示时重新加载，保留同一 xterm 实例和文本。
- 启动：用户打开终端时，xterm 模块加载与后端 shell 启动并行；没有提前创建后台 shell。
- 文件正文：限制为最近 10,000 行、约 4 MiB 估算预算的分页窗口。释放旧页时更新绝对行号和滚动位置，旧内容可通过跳行或“回到开头”重新读取。预算包含正文字符串与行引用估算，不包含高亮、DOM 和编辑草稿。
- 文件树：路径定位只访问目标祖先分支；重验时释放无关折叠分支缓存，不再重读这些目录；选中文件的祖先继续重验。请求完成后删除目录请求身份记录。未修改编辑草稿保留规则。
- 规模测试修正：已有 FileTree 压力样例缺少新增的多选 props，导致读取 undefined.has；补齐样例参数后恢复两万文件渲染验证。

## 实测与回归

`cargo test --manifest-path src-tauri/Cargo.toml terminal::tests:: -- --nocapture` 使用真实 PTY，并打印关闭耗时。

- 改用挂断信号前，连续创建/关闭测试的一个普通 shell 关闭样本为 2.023 秒。
- 修改后三轮样本分别为 22.1 / 15.4 / 23.0 毫秒、19.8 / 11.7 / 7.2 毫秒、19.0 / 77.9 / 11.7 毫秒。仅代表本机测试 shell 的样本，不是桌面交互延迟保证。
- 3 个显式忽略 HUP/TERM 的 shell 批量终止约 2.02–2.05 秒，共享一次宽限期。
- 回归检查重复关闭后的会话弱引用释放、退出后的 PTY 句柄释放、顽固后代停止、背压暂停与恢复、回放容量及多字节字符边界。
- 前端回归覆盖连续读取 30,000 行后的预算与绝对偏移、回到开头、折叠分支重验与再次展开、启动中卸载、部分订阅失败和隐藏/恢复 WebGL。

| 检查 | 结果 |

| Node 22 `npm run check` | 0 errors，0 warnings |

Rust 全量失败项为未修改的 `menu_edit::system_edit_items_do_not_open_search_or_commit`：muda 在 macOS 上要求主线程创建菜单，而该测试在测试线程创建菜单。没有修改产品菜单或跳过该失败来宣称全量通过。

Windows/ConPTY、Linux 和实际桌面长期运行内存曲线尚未验证；mock/单元测试的 WebGL 释放检查不能代替真实 GPU 内存测量。没有生成缺失的交付报告，也不据此宣称跨平台交付门禁通过。

# 多提交读取优化验证

验证环境：Windows，Node.js 26.4.0，Rust 1.99.1。未验证 CI 使用的 Node.js 22，也未验证 macOS/Linux 桌面运行。

## 行为与开销变化

- 多选提交逐份显示已读文件和差异，不再等待全部提交详情完成才开始阅读；加载期间显示已读数量，完整合计在读取结束后显示。
- 后续结果乱序到达时保留当前阅读文件。补入同一文件的其他提交时复用在途和已完成的差异请求，避免重复读取。
- 切换仓库先清除旧选择，避免使用旧仓库的提交 ID 向新仓库请求详情。
- 每份提交的头信息和正文合并为一次 Git 调用。
- 文件目录缓存按仓库、generation、提交和父提交隔离，采用最近使用淘汰，最多保留 32 条且不超过估算 8 MiB。超大条目不缓存；这不是整个应用的内存上限。
- 批量详情和批量差异各保留最多两个在途任务，替换选择或关闭后停止排入旧批次剩余任务。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| `npm run check` | 0 errors，0 warnings |
| `npm test -- --maxWorkers=2` | 44 个测试文件，1044 项通过 |
| 补充乱序到达阅读保持断言后，历史与批量队列专项复测 | 76 项通过 |
| `npm run test:performance -- --ui` | 11 项通过 |
| `npm run build` | 通过；仍有大于 500 kB 的 chunk 提示 |
| `cargo test --manifest-path src-tauri/Cargo.toml` | 245 项通过 |
| `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` | 通过 |
| 版本一致性与 release gate 测试 | v0.2.35 版本一致；7 项通过 |
| `git diff --check` | 通过 |
| `npm run verify:delivery` | 未通过：缺少 `docs/verification/report.json` |

真实 Git 回归建立 16 个提交，先读取全部详情，再读取每个提交的文件差异。`GIT_TRACE` 确认共 16 次 `git log`（原头信息与正文分开需要 32 次），共 16 次 `diff-tree` 和 16 次 `diff --numstat`，差异读取阶段未重复扫描文件目录。该次顺序读取详情和差异耗时约 6.02 秒；没有同环境旧版本计时对照，不声明加速比例。

首次完整前端运行中，首次进入懒加载历史面板的用例超时；单独复测也曾复现，随后单独复测与完整 1044 项复测通过。保留原断言和超时设置，未将其认定为已修复的稳定性问题。

## 验证边界

未测量桌面 WebView 帧率、进程峰值内存或长时间驻留内存。DOM 和请求预算测试不能替代这些测量，也不能据此声明跨平台安装包已经通过验证。

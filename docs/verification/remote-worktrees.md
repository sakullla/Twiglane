# 远端工作树验收记录

验收在 macOS 发起。目标为用户指定的 Linux x86_64 主机。试验创建两个临时 SSH 服务，使用不同主机公钥、普通账号与独立挂载命名空间。两个远端工作树对外呈现相同绝对路径。测试服务和文件在结束时清理。

- A 以公钥登录，B 以临时输入密码登录。两个账号都通过本机 Cliora 开发版连接工具传输并运行了 Twiglane agent。截断第一次上传后仍能重新安装，后续连接复用现有版本。
- 在 A 暂存两项改动，取消其中一项，再提交。独立 SSH 观察到 A 的 HEAD 改变后，测试切断了原连接并丢弃原响应。重连按原操作 ID 确认了该提交，Git 历史只增加一次，B 的 HEAD 和工作区状态与初始状态一致。
- Cliora 的独立远端元数据读取对上了 Twiglane 的工作树标识和起始 HEAD。确认发生提交后，Cliora 读到与回执一致的 HEAD，且保留的一个未暂存文件仍可见。两仓共享协议测试分别覆盖请求和回执。

## 弱网

仅对测试 SSH TCP 连接施加延迟和双向限速。下面的耗时从同一已建立连接内发送请求开始测量。每种条件用 5 和 252 个改动文件验证列表请求数，首个差异为选中的小文件。另从尚有续页的大差异切换到同一小文件。

| 条件 | 实测往返延迟 | 每方向限速 | 5 文件列表 | 252 文件列表 | 小文件差异 | 大差异切换至小文件 |
|---|---:|---:|---:|---:|---:|---:|
| 基线 | 5 ms | 无 | 12 ms | 17 ms | 16 ms | 22 ms |
| 高延迟 | 809 ms | 无 | 815 ms | 819 ms | 819 ms | 827 ms |
| 低带宽 | 11 ms | 32 KiB/s | 33 ms | 273 ms | 37 ms | 703 ms |
| 叠加 | 813 ms | 32 KiB/s | 834 ms | 1072 ms | 839 ms | 850 ms |
| 极端叠加 | 1835 ms | 8 KiB/s | 1892 ms | 2821 ms | 1888 ms | 1938 ms |

在各条件下，大小两组列表各通过一次请求返回。列表分别传输 516 和 8076 字节的 SSH 下行流量。单独请求小文件差异的下行流量为 284 字节。切换时取消旧续读，仅新增 432 字节下行流量。原始数据和候选提交见 [remote-worktrees.json](remote-worktrees.json)。

## 复验入口

在 Twiglane 仓库根目录运行以下命令。SSH 目标需可登录且具有私有挂载命名空间、Git、Python 3 和 OpenSSH。Cliora 使用同一候选的开发构建。

```sh
python3 scripts/remote-worktree/verify-live.py <Cliora开发版路径> <root@测试主机>
python3 scripts/remote-worktree/verify-weak-link.py <user@验证主机>
node scripts/verify-remote-worktree-evidence.mjs
```

窗口流程包含两端前端回归和 Chrome 模拟。已安装的两份正式签名桌面包通过操作系统深链联跑的结果待补。Windows 与 Linux 桌面客户端的安装运行待验证。

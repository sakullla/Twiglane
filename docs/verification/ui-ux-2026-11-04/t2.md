## 1. 方法

1. 读 T1 的 `baseline.md` / `baseline/manifest.json`，并在**未改动前**用 CDP 采集起始页与工作区的 DOM 几何与计算样式
   （每个主题 × 每个窗口：标题栏六个常驻控件、起始页各区块、状态栏各项的尺寸、间距、字号、颜色与实测对比度、是否横向溢出）。
   原始数据：`t2/measurements/t2-baseline.json`。
2. 按量到的偏差改 `src/styles/` 与 `StatusBar.svelte`，只动 T2 scope 内文件。
3. 改完再采一次（`t2/measurements/t2-after.json`），并用 `baseline-shots.mjs --out` 重新出 20 张截图。

> 关于可复现性：这两份 JSON 的采集脚本是**本机一次性脚本，没有入库**。仓库里没有能重跑出同样数字的命令，
> 所以 `t2-baseline.json` / `t2-after.json` 只作为「当时那次采集」的快照，不构成可复跑证据。
> 仓库内可重跑的是 `scripts/ui-preview/baseline-shots.mjs`（截图、控制台错误）与
> `tests/sidebar.spec.ts` 的样式契约（下面 §3 明确写了哪些是取值断言）。返工新增的搜索跳变量同样来自
> 一次性脚本，§2.1 给出的是表达式与结果，没有脚本可以复跑。

> 局限：本会话没有图片查看能力（无 ViewImage/截图预览工具），**没有逐张贴图目视比对**。
> 判断依据是上表的可核对几何与对比度，加上截图产物供人工复核；`baseline.md` 里"截图只证明被截到的那一刻"同样适用。

### 2.1 返工：900×600 下搜索收窄不再跳（P1）

上一轮把 `@media (max-height: 660px)` 里的 `.welcome-recent.searchable` 写成 `min-height: 0`：
搜索结果行数一少，容器就从五行的 218px 缩到 43px，`.welcome-inner` 的 `margin: auto` 重新居中，
搜索框从 y=304 掉到 y=392（88px）。这一档现在按**紧凑行高的实际占位**给 `min-height: 218px`
（900×600 实测五行 217.95px = 行高 40.390625 × 5 + 间隙 2 × 4 + 内边距 4 × 2），
结构、条目数量和垂直居中都不动，只是把「搜索结果变少」这一状态的占位补回五行高度。

| 状态（`?recent=many`、900×600、深色、headless Chrome） | 修复前 搜索框 y / 列表高 | 修复后 搜索框 y / 列表高 |
| --- | --- | --- |
| 未搜索（5 行） | 304 / 218px | 304 / 218px |
| 搜到 1 个（`api-gateway`） | 未测（前一轮没有这个用例） | 304 / 218px |
| 搜不到（`zzzz-no-match`） | 392 / 43px | 304 / 218px |
| 清空搜索后 | 304 / 218px | 304 / 218px |

同一批测量里（`?recent=many` 会多出 28px 高的搜索框，所以这块比 §2 里 5 个仓库的普通起始页高 6px：504 vs 498）：
`.welcome-inner` 恒为 504px 高、y=55；`.welcome` 的 `scrollHeight === clientHeight === 534`
（仍一屏，五行末行底 555 < 状态栏顶 574）；`scrollWidth === clientWidth`（无横向溢出）；
console error 与未捕获异常均为 0。`npm run build` 之后复测一次，四个状态仍是 304 / 218px。
量法（一次性脚本，未入库）：CDP `Emulation.setDeviceMetricsOverride(900×600)` → 打开 `/?recent=many` →
读 `.welcome-search input` 的 `getBoundingClientRect().y` 与 `.welcome-recent` 的矩形 →
用原生 value setter + `input` 事件改查询词再读一次。

## 5. 截图

`docs/verification/ui-ux-2026-11-04/t2/`（5 个界面 × 2 主题 × 2 尺寸 = 20 张，`manifest.json` 记录每张的
`data-theme`、背景色、弹窗标题、行数与 `horizontalOverflow`），另加 `reduced-motion-dark-900x600-start.png`
（`prefers-reduced-motion: reduce` 下：`document.getAnimations() = 0`、卡片过渡 0s、五行最近仓库仍在一屏）。

这张图**不能证明悬停位移是否取消**：静态截图拍不到 `:hover` 状态，两张图逐字节相同只说明「静止那一帧相同」。
有区分力的做法是用 CDP 把指针真实移到卡片上再读计算样式（一次性脚本，未入库，本轮实跑）：

- `prefers-reduced-motion: no-preference`：`:hover` 为真，`transform: matrix(1, 0, 0, 1, 0, -1)`（即 -1px），
  `transition-duration: 0.12s, 0.12s, 0.12s, 0.12s`。
- `Emulation.setEmulatedMedia({ features: [{ name: "prefers-reduced-motion", value: "reduce" }] })`：
  同一张卡片同样是 `:hover` 为真，但 `transform: none`、`transition-duration: 0s`。

仓库内可重跑的那一半在 `tests/sidebar.spec.ts`：普通档必须写 `transform: translateY(-1px)`，
reduce 档必须覆盖成 `none`，`base.css` 的 reduce 块必须全局 `transition: none !important`。
这三条只证明样式文本写了什么，实际观感仍以上面的浏览器实测为准。

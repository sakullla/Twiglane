## 1. 方法

1. 读 T1 的 `baseline.md` 与 T2 的 `t2.md`、`t2/` 截图，先确认这条链路当前长什么样。
2. 用 CDP 打开 mock 预览，在改动视图里采集三种状态的 DOM 几何、可见文本与状态类：
   `single`（选中一个文件）、`multi`（Ctrl+A 全选后的多文件工具条）、
   `empty-staging`（全部取消暂存 + 写一条草稿）。四种组合：深/浅 × 1280×840 / 900×600。
   脚本入库，可复跑：
   `node docs/verification/ui-ux-2026-11-04/t3/measure-changes.mjs --label after --out docs/verification/ui-ux-2026-11-04/t3 --shots docs/verification/ui-ux-2026-11-04/t3`
3. **改动前**：把 9 个文件临时还原成 HEAD 内容（`git show HEAD:<path> > <path>`，先备份到临时目录，采完再拷回并用
   `md5sum` 核对一致），用**同一个脚本**跑出 `before.json` 与 `before-*.png`，让前后两组数字来自同一套表达式。
4. 按量到的偏差只改 T3 scope 内的文件，改完跑 `after` 一组对照，再跑测试与门禁。

> 局限：本会话**没有图片查看能力**，没有逐张贴图目视比对。判断依据是下表的可核对几何与可见文本，
> 24 张截图（`before-*` / `after-*`）供人工复核。`t2.md` §1 的同一条限制在这里同样成立。

## 3. 实际改动

### 3.1 差异工具条分三段（DiffView.svelte、MultiFileDiff.svelte、components.css）

原来 6–10 个控件平铺在同一行、间距一律 8px：位置（上一个/下一个）→ 路径 → 语言 → 历史 → 完整文件 → 布局，
读起来是「七件同等重要的事」。现在按操作顺序包成三段，段间一条 1px 竖线 + 一档内边距：

- **位置与身份**（.diff-toolbar-group.context，唯一 flex: 1 1 auto 的一段）：FileNav + 路径/侧别/增删行数 + 读取中的 spinner。
- **文件动作**：语言选择、此文件历史、只看改动/完整文件。没有文件动作时整段不渲染（hasFileTools），
  不留空段和多余竖线——多文件视图里就不传这几个回调。
- **显示方式**：统一/并排。

多文件工具条同构：已选 N 个文件 | 暂存、取消暂存、放弃 | 全部收起、全部展开、只看改动、统一/并排、退出。
**控件顺序与 tab 顺序都没动**，只是用竖线把「批量动作」和「显示方式」分开，破坏性的「放弃」因此落在批量段末尾，
不再夹在两种动作中间。

竖线是装饰（不承担控件边界），所以用 --border 并在 tests/tokens.spec.ts 的 DECORATIVE_HAIRLINE_RULES 登记了理由；
段内/段外间距靠 gap + padding-left 拉开，没有新增颜色字面值。

多文件工具条控件更多，段内间距收一档（--space-6），并给 .diff-file 加 overflow: hidden + text-overflow: ellipsis：
900×600 实测「已选 14 个文件」78/78 不需要省略，但更窄时也只会省略计数，不会压到批量按钮上。

### 3.2 差异读取失败的恢复入口（DiffView.svelte、App.svelte）

原来失败只剩一句「差异没有读取完成」+ 原因，唯一出路是重新点一次这个文件。现在错误块里多一个「重新读取」，
调用外壳的 loadSelectedDiff()——**和选择文件走同一条读取路径**，token / generation / 写入锁的判断不变，
没有新增绕过防护的读取。多文件视图按块自己重读，不传这个回调就不出现按钮（测试覆盖了两侧）。

### 3.3 空状态说同一件事（DiffView.svelte）

工作区没有任何改动时，左栏说「工作区很干净」，右侧却还在要求「选择一个文件查看差异」。
现在右侧接 fileCount，为 0 时说「工作区没有未提交的改动」并补一句去哪：刷新或切到历史。有改动时文案不变。

### 3.4 文件列表分区线（FileList.svelte、components.css）

冲突 / 未暂存的改动 / 已暂存三段原本只靠表头文字区分，滚动时像一张长表。现在每个分区表头画一条 1px 分区线
（.file-group::before，--border，纯装饰），**第一个表头不画**（上面就是搜索框）。线画在表头自身 30px 高度内，
ROW_HEIGHT、visibleRange、行高与可见行数都不动（实测 28px / 14 行不变）。筛选掉第一个分区时，
新的第一个表头自动接手「不画线」。

### 3.5 提交区状态行（CommitDraft.svelte、components.css）

- **字数提示不再被「全部暂存」挤掉**：原来暂存区为空且有可暂存文件时整条字数提示消失，
  等于「没暂存」把「摘要多长」的信息顶掉。现在两者都渲染，
  .composer-count + .composer-inline-action { margin-left: 0 } 让按钮紧跟计数而不是各吃一个自动外边距。
- **空暂存取警告语义**：状态行加 warn 修饰类，图标改用 --warning-text，与右上「暂存区为空」标签同色；
  「有暂存、只是没写说明」仍是中性灰。这样「还没做」和「做错了」不再长一样（后者是 .composer-error 的危险色）。

没有动：说明框拖动与键盘调高、role="separator" 的取值、更多菜单的固定定位、提交/提交并推送的禁用与 title 原因、
⌘/Ctrl+↵ 键位提示的收起断点（900×600 实测 kbd 仍可见）。

### 3.6 没有改的东西

没有改 Rust、src-tauri/、commands 语义、Git 参数与安全路径；没有新增依赖；没有动
LatestReadQueue / generation / 差异 token / 写入锁 / 草稿保存 / 滚动恢复；没有提交，没有改 workflow state 与 task-run。

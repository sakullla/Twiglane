## 一、实际看到的缺口

先用 mock 预览（`npm run preview:ui`，健康端点返回 `mockApi: true`）在 1280×840 / 900×600 两套窗口分别读历史视图的几何与可访问性状态，
再把历史与命令入口的相关代码读一遍。下面几条是"读到的实际状态"，不是推测：

| 位置 | 改动前读到的值 | 影响 |
| --- | --- | --- |
| 提交列表 listbox | `tabindex="0"`，`aria-activedescendant=null`，`.history-row` 的 `id` 是空串 | 键盘/辅助技术拿不到"当前是哪一条" |
| 键盘移动后的当前行 | `outline: none`（只有列表容器有 2px 焦点环） | 当前行与"鼠标点选"的底色分不开 |
| 分页"回到最新" | 已经在顶部时 `disabled=false`、`title=""` | 点了没有任何反应，也没有说明 |
| 改动 ↔ 历史往返 | 选择保留，但 `scrollTop` 由 300 变回 0 | R3 的"各自仍有效的滚动位置保留"未满足 |
| 提交详情头部 | 没有任何只读标记；复制哈希只换图标 | 看不出这里为什么没有暂存入口（R2、R6） |
| 命令面板 | 分组标题不吸顶；`#palette-input` 没有 `aria-activedescendant` | 滚到中段不知道在哪一组；combobox 与选中项脱节 |
| 分支弹层"其他工作区"行 | 原因只在 `title` 属性里 | R4 要求原因不必悬停即可获取，且与 `BranchPicker` 的「其他工作区」行尾说明不一致 |

## 二、改动

### 1. 历史列表：把"当前行"真正表达出来（R4）

- `.history-row` 增加稳定 `id`（`history-commit-<oid>`），listbox 增加 `aria-activedescendant`（只在当前项已渲染时给出，避免指向不存在的 id）。
  列表容器仍是唯一的 Tab 落点，选项仍是 `role="option"`，键盘模型不变。
- `components.css`：`.history-list:focus-visible .history-row[aria-selected="true"]` 补 2px `--focus` 焦点环。
  选中底色 + 左沿竖条继续表达选择，焦点环只表达"键盘现在在这里"。
- PageDown / PageUp 现在按一屏移动选择（原来只滚动内容、选择留在原处），并沿用 `reveal()` 让当前行进入视口。

### 2. 历史分页与搜索状态（R3、R6）

- "回到最新"在已处于最新时禁用，并用 `title` 说明"已经在最新一条提交"；离开顶部后恢复可用（`滚回最新一条提交`）。
  文案与位置不变，"已加载最新 1–N 条" 保持原样（现有回归依赖它）。

### 3. 往返保留滚动位置（R3）

- 根因：历史面板的读取 `$effect` 依赖 `active`，每次重新激活都完整重读并在成功分支无条件 `scrollTop = 0`。
  改成按"读取签名"（仓库、generation、文件路径、关键词、范围、作者、起止日期、路径）判断：签名变化才回到顶部，
  只是从改动切回来则保持原滚动位置并把状态回写给容器。选择、分页、虚拟窗口逻辑未改。

### 4. 提交详情：只读状态与复制反馈（R2、R6）

- 作者行末尾加"只读"标记（`eye` 图标 + 文字，`title` 说明"不切换分支，也不改动暂存区或工作区"）。
  放在作者行而不是右侧操作区，是因为操作区每多 62px 就从标题列里扣同样的宽度，标题与作者行会被迫折行；
  作者行本身是 `flex-wrap`，多一枚 22px 标记只增加一行而不是挤压标题。代价见"设计判断"。
- `oid-chip` 的复制按钮旁加 `aria-live="polite"` 的 `.sr-only` 播报："已复制提交 <短哈希>"。

### 5. 命令面板（R1、R4、R7）

- `#palette-input` 增加 `aria-activedescendant`，条目补 `id="palette-option-<位置>"`，与两个弹层的 combobox 行为对齐。
- 分组标题改吸顶（`position: sticky` + `--surface` 实底），滚到中段仍知道当前分组；条目名允许省略、禁用原因限宽省略，快捷键列右沿不再随文案长度摇摆。
- 无匹配时在原结论下补一行下一步提示「换个关键词试试，或按 Esc 关闭」，结论 <p> 加 `role="status"`。

### 6. 分支弹层：禁用原因就地可见（R4）

- 处于其他工作区的分支行补行尾说明「其他工作区」（与 `BranchPicker` 同一句），完整原因仍在 `title` 与动作菜单里。
  只加呈现，不改切换、检出、打开工作区的语义。

## 三、设计判断

1. **只读标记放在作者行**：两种候选都实测过。放右侧操作区时标题列从 589.8px 压到 527.8px、详情头从 90.6px 长到 114.3px；
   放作者行后标题列恢复 589.8px，详情头 111.6px（+21px，占 840px 窗口的 2.5%），900×600 下只 +2px（窄布局本来就会折行）。
   选择后者：标题是首要内容，不能让状态标记挤掉它；多出的 21px 仍在 `.commit-head` 的 46% 上限内。
2. **"回到最新"禁用而不是隐藏**：按钮位置固定，禁用 + 原因比"点了没反应"更可预期，也不改变测试与肌肉记忆里的位置。
3. **不把"滚动位置保留"实现为跨仓库保留**：签名包含仓库与 generation，换仓库、刷新历史、改筛选都会回到顶部，避免把旧位置套到新数据上。
4. **分支弹层没有改成虚拟列表**：读代码时发现 `filterBranches`（`src/lib/branches.ts`）对匹配结果做了 200 条截断，并在弹层底部说明"只显示前 200 个"。
   也就是说分支弹层的 DOM 上界已经是 200 行，虚拟化没有收益却会改动键盘/分组两处既有行为；该文件也不在 T4 scope 内。
   因此保留原样，把这个不一致记入 concerns，而不是在 T4 里悄悄改数据层。

## 六、边界与遗留

- 只覆盖 headless Chrome + mock 数据：不代表真实 Git 行为，也不代表 Windows/macOS 桌面 WebView 的字体、缩放与自绘标题栏观感。
- mock 预览的最近仓库只有 5 个，500 个的场景用 `?recent=many` 打开；分支弹层的"其他工作区"行在 mock 里没有对应数据，这一条只有 Vitest 覆盖。
- `src/lib/branches.ts` 的 200 条分支截断不在 T4 scope：分支弹层与分支对话框都会提示"只显示前 200 个"，而表单下拉框（`BranchPicker`）不受此限。这是数据层的既有不一致，留待后续任务统一。
- 未做实机（Windows/macOS 桌面）验证，也未做性能样本对比；改动只涉及 DOM 属性、少量状态判断与小段 CSS，没有新增依赖、没有改 Rust、没有触发任何 Git 写入。

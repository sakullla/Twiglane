## 二、实际改动（4 处源码，全部在 T5 scope 内）

1. **设置弹窗补上头部图标**（`SettingsModal.svelte`）：它是唯一没有 `icon` 的任务弹窗，
   所以标题列比其他弹窗左移 46px（实测 389 vs 435，1280×840 深色），头部也比别人矮 4px（60 vs 64）。
   加 `icon="settings"` 后与临时保存/范围/详情完全同列，层级、间距、关闭按钮位置一致；Modal 语义未变。
2. **任务弹窗的分区标题统一到同一档**（`components.css`）：`.settings-section h2` 原来是
   12px/500/--fg-muted，比它自己的行标签（13px/500/--fg）还小，分组标题读起来像"更小的字"；
   改为 13px/600/--fg，与 `.stash-section-head h2`、冲突侧栏标题同级。
3. **设置分区之间加一条分区线**（`components.css`）：`.settings-section + .settings-section` 加
   `padding-top: var(--space-12)` 与 `box-shadow: inset 0 1px 0 var(--border)`（只在两段之间画，第一段不画）。
   原因是设置在小窗口里现在会滚动（见下表），滚到中段时只靠 12px 间距分不清上下两个分区。
   该线不属于"控件边界"，`border` 发丝线白名单只审 `border*` 声明，因此不需要新增白名单条目；风格与 `.commit-head` 同类。
4. **发布弹窗底部顺序对齐**（`PublishModal.svelte`）：原来是「取消 ｜ 只关联上游 ……… 发布分支」，
   取消单独占最左；改为右侧动作顺序与确认框/详情/范围/临时保存一致：「只关联上游 → 取消 → 发布分支」，
   spacer 在最左。只声明右侧顺序一致：详情弹窗在 spacer 前还放了一个复制按钮，左侧并不完全相同。
   纯子节点顺序调整，未改任何按钮的条件、禁用原因或回调。

没有改：Modal 的 ARIA/焦点圈定/Esc/锁写语义、任何 Git 调用、草稿、行尾处理、写入锁、Rust、依赖。

## 六、主题、尺寸与减少动效

- 4 个组合（深/浅 × 1280×840/900×600）各采 9~10 类弹窗；两套主题读到的盒模型完全相同（样式不含主题分支）。
- 减少动效（900×600 深色 + `prefers-reduced-motion: reduce`）：`document.getAnimations().length = 0`，
  卡片 `animation-name: none`、`animation-duration: 0s`——弹层不依赖动画即可使用；
  截图 `after-reduced-motion-dark-900x600-settings.png`。
- 窄窗（900×600）：所有弹窗都在视口内、无横向溢出；设置与 Git 缺失态需要内部滚动（见上表）。

   事实是该文件早已入库（本轮之前就有 48 条用例），**一直在 `npm test` 的全量计数里**；T4 没有做的只是"修改它"。

2. **命令面板空结果的高度**：T4 写"两条 `<p>` 的类名与内边距没变，视觉位置和卡片高度不变（167.3px）"。
   用 `measure-palette.mjs` 复测：卡片 **167.33px**（这个数字本身对，但它就是包装后的值），
   而 `role="status"` 的包装 `div` 是 block 盒，把原来两个 `<p>` 之间那条 **2px flex gap 取消了**：
   现在两段之间的实际间距是 **0**（`gapBetweenParagraphs: 0`），两段各自的内边距未变（32/16/8 与 0/16/32）。
   所以"高度不变"不成立：同一样式下包装前应为 169.33px，包装后是 167.33px。`t4.md` 已按复测值更正，
   并注明"包装前的值没有实测，只按 flex gap 规则推算"。

## 十、边界与未覆盖

- **发布弹窗在 mock 预览里不可达**：`task.publish` 要求 `upstreamMissing`，mock 的当前分支始终有上游
  （见 `src/lib/commands.ts` 的 `available`），所以没有它的截图与几何。底部顺序改动由
  `tests/modal.spec.ts` 的新用例覆盖，观感待人工复核。
- **从命令面板打开的弹窗，Esc 后焦点落到 BODY（返工已修）**：上一轮 4 个组合里设置/临时保存/分支/范围/合并关闭后
  `document.activeElement` 都是 `body`：面板与任务弹窗在同一批更新里换位，Modal 在 `onMount` 抓到的"打开前焦点"
  是随即卸载的面板输入框，交回去就落空。
  返工的修法不是猜入口，而是把**打开面板前的有效焦点**记下来交给弹窗：
  `App.svelte` 在 `openPalette()` 记录 `document.activeElement`（排除 `body`），`openTask()` 在关面板的同一批更新里
  把它算成 `taskReturnFocus` 传给 `Modal` 的 `returnFocus`；`Modal` 只在传了且仍连在文档里时用它，否则保持原语义
  （打开瞬间的 `activeElement`），因此没有改变焦点圈定、Esc、锁写这些既有语义。
  只有打开面板前焦点确实不可用（刚进界面就按 ⌘K，焦点还在 `body`）才走明确后备：落到主内容区
  `main.content`（`tabindex="-1"`，只可编程聚焦、不进 Tab 序）。回归用例见 `tests/app-shell.spec.ts`
  "命令面板打开的任务弹窗：Esc 后焦点回到打开面板前的控件，不落到 body"。
  **仍未覆盖**：`task.remote` 走的是 `RepoDialogs.svelte`（不在 T5 scope，本轮未改），从命令面板打开远程弹窗后
  Esc 仍回到 `body`；如需对齐，应由后续任务在同一个 `returnFocus` 口径下补齐。
- **设置在小窗口需要滚动 31px**（`四）：主动接受的代价。若后续要恢复"600 高一屏"，应优先收分区线那 26px，
  而不是把字号改回 12px。
- **只覆盖浏览器 + mock 数据**：`?merge=conflict` 的冲突文件只有 3 个、按钮文案固定；长分支名、超长冲突说明、
  真实 Git 的 200+ 冲突文件没有在弹窗里单独取数（R7 的清单/差异部分由 T3/T4 覆盖）。
- **没有实机验证**：Windows/macOS 桌面 WebView 的字体、缩放、自绘标题栏观感未覆盖；也没有性能样本对比。
- **没有目视比对截图**（见 `一 的局限）；像素级观感需要人工看图。
- 返工没有改 Rust、没有新增依赖、没有触发任何 Git 写入、没有提交、没有改 workflow state / task-run。

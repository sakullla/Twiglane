# 本地未提交读取性能验证

本记录来自 Windows 上的生成仓库与真实 Git，不是桌面 WebView 帧率或跨平台发布验收。耗时是同机单次对比，Rust 使用 test/debug 构建，不代表稳定的 P95。

## 改动与边界

- 完整补丁直接使用解析出的行数和二进制标记，省去第二次 `git diff --numstat`。截断补丁仍查询完整统计，按块暂存仍重新核对快照。
- 状态中的已暂存、未暂存统计通过现有读取调度器并发执行；写锁内仍顺序执行。
- 未跟踪文件列表统计移入阻塞线程。文本单文件最多统计 2 MiB，每次状态读取最多扫描 16 MiB 内容；超过预算的统计为空，文件仍保留在列表中。二进制仍由最多 8,000 字节的头部探测识别。边界探测最多额外读取一字节，以防文件在读取期间增长而误报完整行数。
- 每次刷新仍向 Git 读取差异；补丁快照、文件、暂存侧与分页一致时复用行数组，避免重新排版和分词，同时采用新的 generation。二进制预览不做此内容复用。
- 同时修正现有分支测试夹具的类型声明，使其允许字符串 upstream；不改变分支产品行为。

## 同机对比

命令：

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml --features performance-tests uncommitted_reads_at_scale -- --nocapture
```

夹具生成 5,000 行已跟踪文本后将其替换为一行，连续读取差异 10 次；随后生成 104,000,000 字节未跟踪文本并刷新状态 3 次。基线在修改实现前运行，优化后增加进程数和未知统计的断言。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 10 次未提交差异读取 | 1.455337 s | 0.9618033 s |
| 上述读取启动的 `git diff` 数量 | 20 | 10 |
| 含 104 MB 未跟踪文本的 3 次状态刷新 | 4.1586199 s | 0.2787267 s |

大文件场景的收益来自省去列表中的全量行数统计；此时行数留空，打开文件仍可查看差异及其统计。

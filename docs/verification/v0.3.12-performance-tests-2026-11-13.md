# v0.3.12 性能、测试整理与验证

环境：macOS arm64、Rust/Cargo 1.98.1。早期基线使用 Node.js 22.23.5；最终按用户要求升级为 Node.js 26.13.0 / npm 12.2.2。包含文件与终端资源优化、Git/大文本优化，以及远端 `b164b8c` 的面包屑导航和 `5add30a` 的 Markdown 头属性展示改动。

## Git 与大文本

- 历史差异复用固定提交之间的原始补丁和解析结果。缓存按仓库、Git 程序、完整命令参数、generation、预览上限和文本模式区分；最多 8 项、估算 8 MiB，超大结果不缓存。工作区读取和暂存写入仍重新核对 Git。
- 文本分页保存行号到字节位置的有界索引，最多 16 个文件、每个 64 个位置，不缓存正文或打开句柄。依据打开文件的元数据版本复核；文件替换、取消、CRLF、无末尾换行及超长行均有回归。
- 补丁同时受字节和结构预算约束：最多解析 100,000 行，单行显示最多 64 KiB；被裁剪的代码块不可按行或按块暂存。其他完整代码块仍可暂存，展示和写前复核使用一致的快照判定。
- 输出边界切在 UTF-8 字符中间时保留有效前缀，真正的非法编码仍报错。正文中的 `GIT binary patch` 不再误判为二进制。
- 本地文本比较限制每侧 50,000 行、2 Mi 字符和单行 32 Ki 字符，保持 Unicode 边界；不改原始编辑文本。移除大数组展开调用导致的栈溢出风险，纯新增/删除不创建无用的二维对齐表。
- Git 输出超限或读取失败时显式终止并回收子进程；已取消的读取不会再启动进程。

独立命令 `npm run benchmark:git -- text` 的本机样本（未优化 Rust 构建）：

| 场景 | 不复用缓存 | 复用缓存 |
| --- | --- | --- |
| 104 MB 文本，第 100,000 行后连续读取 8 页 | 619.85 ms | 4.63 ms |
| 5,000 行历史差异读取 8 页 | 197.82 ms，8 次 diff | 86.56 ms，1 次 diff |

文本缓存组预先读过前页；首次定位未读区域仍需要扫描。Git 两组均先完成环境探测和目录预热。结果不是桌面延迟或整机内存保证。

## 测试整理

| 同机运行 | 测试数 | 耗时 |
| --- | --- | --- |
| 原套件，2 个 fork worker | 1426 | 64.01 s |
| 相同套件，4 个隔离线程 | 1426 | 32.05 s |
| 测试整理后（Node 22、Markdown 改动合入前），4 个隔离线程 | 1335 | 21.06 s |
| 最终 Node 26 套件，4 个隔离线程 | 1338 | 22.21 s |

测试整理后的范围有变化：11 项预览检查移到独立集成入口，删去约 80 项重复的 CSS 数值/源码断言，2 项计时用例移为 benchmark，并合入远端新增的 2 项导航测试；最终又合入 3 项 Markdown 测试。因此不能把全部耗时下降都归因于执行器。

- 8 个小型纯逻辑文件合并为编辑文本、读取生命周期两个套件，使用 Node 环境；组件仍使用 happy-dom。保留文件间 mock 隔离。
- 主题保留键集合、主题切换、对比度、焦点和减少动效契约，移除大量精确颜色、像素和已被行为测试覆盖的源码断言。
- 多提交元数据测试使用根提交与两个后续提交，代替 16 个重复提交，继续核对 Git 调用次数。
- macOS 菜单单元测试只验证事件路由，不再在测试线程创建要求主线程的原生菜单；这不等同于验证原生菜单的真实交互。
- `npm run test:integration` 保留 25 项预览接线、虚拟渲染、并发和取消检查，CI 单独执行，未通过排除集成检查来宣称整体门禁更快。
- benchmark 不再使用 Vitest/Rust 测试注册，也不由 CI 执行。入口为 `benchmark:git`、`benchmark:status`、`benchmark:text`；移除了普通测试中的计时输出与 1.5 秒性能阈值。资源上限与挂起保护仍是功能回归。
